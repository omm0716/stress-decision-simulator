프로젝트 아이디어 실행 가능성(Feasibility) 및 바이브 코딩 분석 보고서

[0. 총평 및 피드백: "두 가지 생각의 완벽한 조화"]
--------------------------------------------------------------------------------
보내주신 두 가지 관점(1. 뾰족한 차별화 앵글 / 2. 빠른 완성 중심의 바이브 코딩)은
서로 충돌하는 것이 아니라, "1단계: 일단 빠르게 작동하는 뼈대 만들기(Ship)"와
"2단계: 내가 직접 쓰면서 뾰족한 나만의 변수 하나 얹기(Differentiate)"라는
가장 이상적인 사이드 프로젝트 사이클을 형성하고 있습니다.

아이디어 1, 2, 3번 모두 매력적이지만 '기술적 복잡도'와 '외부 의존성'에 따라
첫 주말 안에 완성할 수 있는 가능성(실행 난이도)에는 분명한 차이가 있습니다.


================================================================================
[항목 1] 계산기 / 시뮬레이터 : "의사결정 스트레스 테스트"
================================================================================
■ 핵심 콘셉트
- 단순 수익률/결과 산출이 아닌 최악의 시나리오(하위 5%), 멘탈 비용, 기회비용 시각화
- 극히 개인적인 소비/투자 성향 슬라이더(배달음식 참기 횟수, 경조사 이벤트 등)

■ 실행 가능성(Feasibility) 분석
1. 개발 난이도 : [최하 (매우 쉬움)]
   - 서버/데이터베이스(DB)가 전혀 필요 없는 Pure Client-Side(HTML/JS or React) 앱.
   - 외부 API 연동이나 결제, 회원가입 없이 오직 '수식'과 '인풋 UI'만으로 작동.
2. AI 바이브 코딩 적합도 : [최상]
   - AI는 수식 계산 로직, 슬라이더/인풋 컴포넌트, 차트 시각화(Chart.js, Recharts 등)
     코드를 에러 없이 가장 완벽하고 빠르게 뽑아냅니다.
3. 배포 및 유지보수 난이도 : [최하 (유지비 0원)]
   - Vercel, Netlify, GitHub Pages 등을 통해 명령어 한 줄 또는 클릭 몇 번으로 무료 배포 가능.
   - 서버가 없으므로 터질 위험도 없고, 사후 유지보수 스트레스가 0에 수렴.
4. 발생 가능한 병목 지점
   - 계산 공식(수식) 설계에 시간을 너무 많이 쓰면 기획 단계에서 멈출 수 있음.
   - 해결책: 1차는 엑셀 수준의 단순 계산기로 시작하고, 슬라이더/최악 시나리오 계산은
     기본 뼈대가 돌아간 뒤에 함수 1개씩 추가.

■ 추천 1차 MVP 스코프 (주말 1일 컷)
- 1단계: 기본 인풋값(시드, 기간, 기본 변수) -> 결과 출력 화면
- 2단계: '최악 시나리오(MDD/원금 손실 등)' 계산 토글 스위치 및 그래프 시각화 추가
- 3단계: 나만의 위트 있는 슬라이더(예: 배달앱 결제 억제 횟수) 1~2개 추가

★ 종합 실행 가능성 평점: 5.0 / 5.0 (가장 추천하는 첫 시작)


================================================================================
[항목 2] 데일리 브리핑 : "극단적 노이즈 컷과 1줄 행동 강령"
================================================================================
■ 핵심 콘셉트
- 광고, 어그로 기사 무조건 탈락시키는 네거티브 필터링
- "그래서 내가 오늘 해야 할 행동 1개"로 요약되는 30초 컷 브리핑

■ 실행 가능성(Feasibility) 분석
1. 개발 난이도 : [중상 (다소 복잡)]
   - 뉴스 수집(RSS 또는 크롤링) + LLM API 요약 + 발송/표시(웹/텔레그램/이메일) 구조.
   - 주기적으로 데이터를 긁어와 요약하는 '백엔드 스케줄러(Cron)' 구축이 필수적임.
2. AI 바이브 코딩 적합도 : [중]
   - 파이썬 스크립트 작성 자체는 AI가 쉽게 짜주지만, 크롤링 대상 웹사이트의 구조 변경,
     봇 차단, 프롬프트 요약 품질 편차 등 '환경적 예외 처리'가 빈번함.
3. 배포 및 유지보수 난이도 : [중]
   - 주기적 실행을 위해 GitHub Actions, Supabase Edge Functions, 소형 VPS 등이 필요.
   - 매일 LLM API(OpenAI/Gemini 등) 호출 비용이 소액이지만 지속적으로 발생함.
4. 발생 가능한 병목 지점
   - 네거티브 필터링 규칙과 프롬프트 튜닝에 너무 많은 시간을 뺏길 수 있음.
   - 크롤링 타겟 사이트가 접속을 막거나 구조를 바꿀 때마다 스크립트가 깨짐.

■ 추천 1차 MVP 스코프 (주말 2일 컷)
- 웹 대시보드나 이메일 템플릿부터 만들지 말 것.
- 1단계: 파이썬 스크립트로 네이버/구글 RSS 3곳 긁어와서 Gemini/OpenAI API로 요약.
- 2단계: 결과를 본인 텔레그램 봇으로 1일 1회 자동 쏘는 GitHub Actions 연동.

★ 종합 실행 가능성 평점: 3.5 / 5.0 (결과물 만족도는 높으나 백엔드/스케줄러 관리 필요)

[항목 3] 브라우저 익스텐션 : "작업 공간으로의 파이프라인 적재"
================================================================================
■ 핵심 콘셉트
- 텍스트/아티클 드래그 시 내 커스텀 템플릿으로 노션/옵시디언/마크다운 자동 적재
- 특정 사이트(공시, 논문, 커뮤니티 등)의 복잡한 데이터를 표로 재정렬하는 커스텀 리더

■ 실행 가능성(Feasibility) 분석
1. 개발 난이도 : [중]
   - 크롬 익스텐션 최신 규격(Manifest V3)의 배경 스크립트(Service Worker),
     콘텐츠 스크립트, 팝업 간의 메시지 통신 구조 이해 필요.
   - 노션 API 또는 로컬 파일(옵시디언) 저장 연동 시 토큰 발급 및 권한 처리 필요.
2. AI 바이브 코딩 적합도 : [중상]
   - 익스텐션 보일러플레이트(Manifest, Popup, Content Script)는 AI가 잘 작성함.
   - 다만 Manifest V3 보안 제약(외부 스크립트 실행 제한 등)으로 인한 버그 발생 시
     AI 디버깅 티키타카가 몇 차례 필요할 수 있음.
3. 배포 및 유지보수 난이도 : [상 (스토어 등록 시)]
   - 본인 크롬 브라우저에서 '개발자 모드로 로드'해서 혼자 쓰는 것은 0원, 즉시 가능.
   - 크롬 웹스토어에 공식 배포하려면 개발자 등록비(5달러)와 구글 심사 기간(며칠~수주) 소요.
4. 발생 가능한 병목 지점
   - 노션 API 연동 인증(OAuth) 처리하다가 주말 다 갈 수 있음.
   - 해결책: 1차는 노션 API 대신 [클립보드에 마크다운 양식으로 자동 복사] 기능으로 단순화.

■ 추천 1차 MVP 스코프 (주말 1.5일 컷)
- 1단계: 웹페이지에서 드래그 후 우클릭(또는 단축키) -> 내 정량 템플릿으로 마크다운 변환
- 2단계: 클립보드 자동 복사 + 토스트 알림 (옵시디언/노션에 바로 Ctrl+V 가능)
- 3단계: 본인이 실제로 매일 쓰는 게 검증되면 그 후 노션 API 연동 추가

★ 종합 실행 가능성 평점: 4.0 / 5.0 (혼자 쓰는 용도로는 매우 실용적이고 효능감 높음)
